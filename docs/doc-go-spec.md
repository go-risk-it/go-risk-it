# Doc.go Specification

Living architecture documentation for go-risk-it. Every non-excluded package
gets a `doc.go` file that embeds its architectural role directly in the source.

## Layer Taxonomy

Each package belongs to exactly one layer. The layer determines import rules,
testing expectations, and the package's role in the dependency graph.

| Layer | Description | Import constraints |
|-------|-------------|-------------------|
| `api` | Data transfer objects (request/response/messaging types) | May only import other `api/` packages |
| `kernel` | Shared infrastructure (config, ctx, data, errors, bus, metrics) | Never imports game/ or lobby/ |
| `data` | Database access and persistence | Never imports `logic/` or `web/` |
| `events` | Event bus infrastructure | Never imports `logic/` or `web/` |
| `events-domain` | Domain event payload types | May import `logic/` types for payloads |
| `logic` | Business rules and domain services | Never imports `web/` or `api/` |
| `shared` | Cross-cutting domain types (errors) | Imported by all layers |
| `infrastructure` | Pure utilities with no internal deps | Leaf packages — no internal imports |
| `web` | HTTP/WS handlers, middleware, routing | May import all other layers |
| `test` | Test-only packages | Never imported by production code |
| `wiring` | fx Module aggregation roots | One file, fx.Module only |

## Package Classification

### Exclusions (no doc.go required)

These packages are excluded from doc.go requirements entirely:

| Package | Reason |
|---------|--------|
| `internal` (root) | Wiring root — single `internal.go` with fx.Module |
| `*/sqlc` | Auto-generated by sqlc |
| `*/mocks` | Auto-generated by mockery |

## Templates

### Full-tier template

```go
// Package <name> <one-line summary>.
//
// <Expanded description — what problem this package solves, what invariants
// it maintains, and how it fits into the game engine.>
//
// # Layer
//
// Logic — business rules for <domain concept>.
//
// # Key Types
//
// [Service] is the primary interface. It provides methods for <operations>.
//
// [serviceImpl] implements [Service] using <dependencies>.
//
// # Dependencies
//
//   - [region.Service] for territory ownership queries
//   - [player.Service] for active player lookups
//   - [db.Querier] for database access within transactions
package <name>
```

### Lightweight-tier template

```go
// Package <name> <one-line summary>.
//
// <Optional expanded description.>
//
// # Layer
//
// Infrastructure — <role description>.
package <name>
```

## Tier Assignment Algorithm

Given a package `P` with import path `github.com/go-risk-it/go-risk-it/internal/<suffix>`:

```
1. If suffix contains "/sqlc" or "/mocks" → EXCLUDED
2. If suffix == "" (internal root) → EXCLUDED
3. If len(GoFiles) == 1 AND GoFiles[0] matches "<lastSegment>.go" → WIRING (excluded)
4. If "service.go" in GoFiles AND len(non-test GoFiles) > 2 → FULL
5. Otherwise → LIGHTWEIGHT
```

## Layer Assignment Algorithm

The layer is determined by the package path prefix. Explicit mappings are
checked first (see `expectedLayer` in arch_test.go), then prefix-based rules:

```
1. starts with "game/api/" or "lobby/api/" → api
2. starts with "kernel/" → kernel
3. starts with "game/data/" or "lobby/data/" → data
4. starts with "game/events" or "lobby/events" → events-domain
5. starts with "game/logic/" or "lobby/logic/" → logic
6. starts with "game/publisher" or "lobby/publisher" → web
7. starts with "data/" → data
8. starts with "web/" → web
9. starts with "testing/" or == "testonly" → test
10. == "logic" → wiring
```

## Validation Rules (enforced by arch_test.go)

1. **TestArch_DocGoExists**: Count of packages with doc.go >= `minDocGoCount` baseline
2. **TestArch_DocGoSections**: Full-tier packages must have `# Layer`, `# Key Types`,
   `# Dependencies` headings. Lightweight must have `# Layer`.
3. **TestArch_DocGoLayer**: The paragraph after `# Layer` must start with the
   expected layer name for that package.

All rules only check packages that already HAVE a doc.go — they enforce
correctness of existing files, not existence of new ones. Existence is
ratcheted via the baseline count.
